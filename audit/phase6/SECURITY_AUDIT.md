## ۱. جمع‌بندی وضعیت

| محور | وضعیت | شواهد |
|---|---|---|
| اعتبارسنجی دادهٔ ورودی | ✅ خوب | isValidState/isValidAttempt: تایپ همهٔ فیلدها، xp ≥ ۰ و متناهی، عضویت source در ۵ مقدار مجاز، reviewPlan اختیاری اما در صورت حضور سخت‌گیرانه؛ import خراب → null نه کرش (آزمون) |
| جلوگیری از دستکاری وضعیت پیشرفت | ◐ | دستکاری از DevTools (ویرایش localStorage) به‌طور ذاتی قابل جلوگیری نیست (اپ محلی بدون سرور)؛ اما ورودی نامعتبر (xp منفی، تلاش بدون source، شناسهٔ پرسش ناشناخته) در import و بازسازی وضعیت رد/نادیده گرفته می‌شود (آزمون) — امتیاز/زنجیره با دستکاری مستقیم localStorage قابل افزایش است |
| جداسازی دادهٔ دانش‌آموزان | ❌ | **یک STORAGE_KEY واحد برای کل دستگاه** — دو دانش‌آموز روی یک دستگاه دادهٔ مشترک دارند؛ جداسازی نیاز به پروفایل چندکاربره دارد (خارج از محدودهٔ این نسخه) |
| سطح دسترسی والد/دانش‌آموز | ◐ | بدون احراز هویت (اپ کاملاً محلی)؛ گزارش والد از همان منوی برنامه در دسترس دانش‌آموز نیز هست؛ داده‌ای حساس اداری وجود ندارد اما «رمز/قفل والد» وجود ندارد |
| ذخیره‌سازی و بازیابی | ✅ | round-trip سالم؛ خرابی JSON/ساختار بد → حالت اولیه بدون کرش؛ خطای Quota/حالت خصوصی → ادامهٔ بی‌صدا بدون ذخیره (آزمون) |
| سازگاری دادهٔ قدیمی با نسخهٔ جدید | ✅ | کلید v3 از قبل ثابت بوده؛ ساختار قدیمی (بدون reviewPlan، source فقط practice/exam) پذیرفته و موتور تطبیقی از آن وضعیت مهارت می‌سازد (آزمون اختصاصی)؛ فیلد جدید اختیاری است |
| امنیت اطلاعات شخصی کودکان | ✅ قوی | تنها دادهٔ شخصی: studentName (برش به ۳۰ نویسه)؛ **هیچ تماس شبکه‌ای در src وجود ندارد** (grep: بدون fetch/axios/WebSocket)؛ بدون آنالیتیکس/تبلیغات؛ خروجی JSON صرفاً با اقدام خود کاربر؛ React از رندر ناامن (dangerouslySetInnerHTML/eval/innerHTML) استفاده نمی‌کند |
| مدیریت خطا و خرابی ذخیره‌سازی | ✅ | ErrorBoundary دور برنامه (بدون ارسال داده به بیرون)؛ همهٔ I/O محلی try/catch |
| دسترس‌پذیری و موبایل | ✅ پایه | lang=fa dir=rtl، viewport موبایل، aria-label/role/aria-live/progressbar در کارت پرسش و جریان درس، عناصر فرم با label/aria-describedby؛ اسکرین‌شات موبایل ۳۹۰px در docs موجود؛ هیچ آزمون خودکار a11y (مثل axe) اجرا نشده — پوشش کامل ادعا نمی‌شود |

## ۲. یافته‌ها

| شدت | شرح | تکلیف |
|---|---|---|
| متوسط | **کش سرویس‌ورکر ثابت (cache-first + CACHE_NAME `v1` بدون نسخه‌بندی):** کاربر بازگشتی ممکن است تا مدتی HTML/باندل قدیمی را ببیند (به‌روزرسانی دیپلوی با تأخیر برای او اعمال می‌شود)؛ داده‌ای آسیب نمی‌بیند ولی انتشار نسخهٔ جدید برای کاربران فعلی تضمین فوری ندارد | مستند؛ پیشنهاد: network-first برای سند اصلی یا نسخه‌بندی CACHE_NAME در هر build (تست مرورگری لازم دارد؛ در این ممیزی بدون آزمون مرورگر تغییر داده نمی‌شود) |
| متوسط | نبود جداسازی چنددانش‌آموزی روی یک دستگاه (کلید واحد) | مستند؛ نیازمند قابلیت پروفایل (نسخهٔ بعد) |
| جزئی | عدم محدودسازی بازهٔ timestamp/hintsUsed در اعتبارسنجی تلاش (مقدار معقول از خود اپ می‌آید؛ فقط import دستی می‌تواند عدد عجیب تزریق کند و صرفاً در سنجه‌ها اثر می‌گذارد) | مستند |
| جزئی | دستکاری مستقیم localStorage (بدون import) اعتبارسنجی نمی‌شود — ذاتیِ اپ محلی؛ برای محیط کلاس می‌توان در نسخهٔ بعد checksum ساده افزود | مستند |

## ۳. حریم خصوصی — اعلام صریح

- هیچ داده‌ای از دستگاه خارج نمی‌شود (بدون هیچ درخواست شبکه در کد برنامه).
- هیچ دادهٔ حساس (نشانی، تصویر، سن دقیق، شماره) جمع نمی‌شود؛ فقط نام اختیاری نمایشی.
- گزارش ممیزی و تصاویر فاز ۷ هیچ دادهٔ واقعی دانش‌آموز ندارند (داده‌ها ساختگی/تست‌اند).
